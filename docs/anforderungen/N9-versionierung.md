# N9 – Versionierung

- N9 Versionierung nach Semantic Versioning, Start 1.0.0 (2026-11-12). Einzige Quelle der Versionsnummer ist `package.json` (`src/version.ts`). Major: inkompatible Änderungen an Export-/Link-Format; Minor: neue Funktionen/Eingaben oder bewusst geänderte Rechenmodelle bzw. Standardwerte; Patch: Fehlerkorrekturen, Texte, Darstellung. Trunk-Based ohne gesonderte Releases. Version und Changelog werden automatisch aus den Commit-Nachrichten nach Conventional Commits abgeleitet (`feat` → Minor, `fix`/`perf` → Patch, `!`/`BREAKING CHANGE:` → Major, übrige Typen → keine Version): Nach jedem Push auf `main` berechnet `scripts/release.ts` die Version ab dem letzten Release-Commit, schreibt `package.json`, `package-lock.json` und einen Abschnitt „## x.y.z – JJJJ-MM-TT“ (Rubriken Inkompatible Änderungen, Neu, Fehlerkorrekturen, Verbessert) in `CHANGELOG.md` und committet `chore(release): x.y.z`. So entstehen bei paralleler Entwicklung keine Versionskonflikte; PR-Titel werden geprüft. Ein Squash-Commit, der in seiner Nachricht mehrere Änderungen als Listenzeilen im Commit-Format enthält (`* feat: …` bzw. `- feat: …`), ergibt je Änderung einen eigenen Changelog-Eintrag statt eines Sammeleintrags aus dem PR-Titel; das Repository übernimmt beim Squash-Merge dafür die Commit-Nachrichten des PRs. *(Test: release)* Die Version steht im Kopf des Rechners und in der Fußzeile (Link auf `changelog.html`), auf allen Dokumentseiten und im JSON-Export (`appVersion`, beim Import ignoriert). *(Test: version)*
